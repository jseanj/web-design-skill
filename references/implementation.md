# 网页实现与校验

以下工程建议用于把视觉方法落实到网页，不作为统一数值规范。根据项目、内容和已有设计系统调整；无需为了使用本 skill 更换框架或安装依赖。

## 把年代性的参数转换为设计意图

| 历史做法 | 保留的意图 | 实现时如何判断 |
| --- | --- | --- |
| 800/1000 像素安全宽度 | 必要信息在目标设备可见范围内 | 用实际视口与内容断点验证，不固定套用历史宽度 |
| 宽屏背景与中心区域 | 关键内容稳定、背景可延展 | 将内容容器、视觉主体、装饰背景分别布局 |
| 整页旋转 | 打破惯常构图，制造动势 | 优先旋转背景或短标题，长正文保持易读 |
| Flash 与当时的多媒体 | 用动态和交互加强主题 | 使用项目支持的网页能力；静态内容与主要操作不能依赖动画播放 |
| 悬停显示详情 | 在简洁页面中提供进一步信息 | 同时提供点击、触摸、键盘可访问的入口 |
| 小字增强精度感 | 字号对比与细节层次 | 使用真实、准确、可读的内容，不用乱码或无法辨认的微字 |
| 当年的屏幕调查与趋势 | 根据用户环境调整表现 | 依据当前项目设备要求；未研究时不要引用旧数据当作现状 |

## 构图与内容分离

- 用 Grid/Flex 或项目已有布局系统组织信息；绝对定位用于局部视觉关系时，检查文字变长、缩放与换行后的空间。
- 让装饰层独立，不参与焦点顺序；纯装饰图形可设置 `aria-hidden="true"`，覆盖在内容上方时避免拦截点击。
- 斜面、裁切或屏幕边缘的越界应发生在装饰层。不能用全局隐藏横向溢出来掩盖正文布局错误。
- 视觉中的阅读顺序与 DOM 顺序保持一致，避免桌面上看似合理、键盘或窄屏上却跳来跳去。

## 图像与取景

主图先确定主体位置、裁切边界与文字所在区域，再选择 `object-fit`、`object-position` 或背景定位。桌面裁切不一定适合手机，可换裁切、换图或把图片移到文字上下。

为“断臂之美”记录必须保留的特征；为“全屏大视野”记录可被裁掉的背景。不要把标题、按钮或关键说明烘焙进背景图片。主体与文字冲突时，先换位置和裁切，再考虑局部遮罩或底板。

尺寸与加载策略匹配展示需求，给主要图片稳定的宽高或比例，避免加载后挤动内容。大图不是无限增加资源体积的理由。

## 排版与响应

建立有职责的标题、正文、说明和数据层级。同类信息保持稳定样式；内容不同不必强迫套进相同卡片。

窄屏时依据任务顺序重排，而非等比缩小整个桌面画布。检查：

- 巨型标题能否自然换行，中文是否出现孤字或不合理断句。
- 正文是否仍可读，关键按钮是否便于触摸，长数字和标签是否溢出。
- 桌面的左右分割、曲线流程、偏移构图，能否转成清晰的上下顺序。
- 固定高度是否截断内容；必要时改为内容撑开或合适的最小高度。
- “欲擒故纵”的留白是否让用户误以为页面已经结束。

可按内容选择测试宽度；没有明确设备要求时，约 390 像素和 1440 像素可作为起始检查点，再检查发生换行和重排的临界宽度。这是检查样本，不是保证所有设备兼容的结论。

## 交互与信息图

按钮用真实按钮语义，导航用链接语义；图标需要清楚的可访问名称，焦点要可见。不要让关键信息只依赖颜色、悬停或动画。动效服从阅读顺序，尊重减少动态效果的用户偏好。

“文字衣橱”的收纳要保留摘要、标签或数量，让用户知道还有什么。主要行动应有可观察结果；若后端尚未连接，明确原型状态，不假装提交成功或已产生真实订单。

“你看起来很好吃”的图形必须忠实于信息关系：

- 定量对比使用一致单位与比例，标出必要的标签、来源或口径。
- 纯定性关系不使用貌似准确的份额；箭头不暗示不存在的因果或步骤。
- 同类对比字段对齐，流程起止明确，分支条件可辨。
- 关键数据同时提供文字表达；不能只把图表保存成没有说明的图片。

## 验证与交付

沿用项目现有的检查与运行方式，不为纯视觉小改动另造测试工程。能运行时预览实际页面，检查窄屏、桌面及关键重排位置；点击主按钮、导航与收纳入口，检查键盘焦点、内容完整性、图片缺失和溢出。

把“已运行”“已截图查看”“已操作交互”分开记录。无法预览时可完成代码检查并指出未验证的视觉部分。交付时给出可打开的文件或项目入口，以及少量影响结果的设计依据；用户只要成品时不用附一份冗长设计论文。
